# 快速驗收：公開網頁版敲磚塊遊戲

## 前置條件

- 從專案根目錄執行命令。
- 網頁專案位於 `web/`，並使用 Sites starter 所產生的套件管理器與 lockfile。
- 已安裝可用的 Node.js／套件管理器；既有 Python 虛擬環境仍可執行 Pygame 範例。
- 手動驗收準備桌面鍵盤、計時工具，以及 5 位第一次接觸網頁版本的玩家。

## 專案安裝與靜態檢查

在網站第一次建立或依賴尚未安裝時，於 `web/` 安裝依賴：

```bash
cd web
npm install
```

預期結果：依 Sites starter 的 lockfile 完成安裝，沒有需要登入或設定遊戲資料庫的步驟。

執行網站建置：

```bash
npm run build
```

預期結果：建置成功，產生 Sites 可用的 Workers 相容輸出；沒有 TypeScript、模組解析或路由錯誤。

回到專案根目錄確認既有桌面檢查點仍可編譯：

```bash
cd ..
./.venv/bin/python -m py_compile Day2/prj07_win.py
```

預期結果：命令成功結束；網頁化沒有修改既有 Python 檔案的語法或依賴。

## 啟動本機預覽

在 `web/` 啟動 Sites 專案的開發命令：

```bash
npm run dev
```

預期結果：本機網址可開啟單一遊戲頁面，顯示遊戲專屬標題、操作提示、遊戲區、45 塊磚、底板、球、`Lives: 3` 與 `Score: 0`。

## 驗收情境

### 情境一：公開入口與初始狀態

使用本機預覽或已部署的公開網址，在未登入的桌面瀏覽器開啟頁面。確認不需安裝 Python／Pygame、不要求登入，且每次重新整理都回到 45 塊磚、3 次生命與 0 分。

### 情境二：開始遊戲與底板控制

按 Space 發球；使用 Left／Right 與 A／D 移動底板。確認底板不超出左右邊界，放開按鍵後不會持續自行加速，Space 不會使頁面意外捲動。

### 情境三：牆面、底板與磚塊碰撞

遊玩至球碰到左右牆、上牆、底板與磚塊。確認球按既有規則反彈；每擊破一塊磚只移除一次並增加 10 分。

### 情境四：SC-003，三次確認勝利結果

進行 3 次彼此獨立的完整清板測試。每次記錄最後一塊磚消失的時間，確認 1 秒內顯示 `You Win` 與 `Press SPACE to restart`，且最後一次 10 分已計入分數。

### 情境五：SC-004，三次確認 Game Over 結果

進行 3 次彼此獨立的失敗測試；每次在尚有磚塊時讓球遺失三次，確認顯示 `Game Over` 而非 `You Win`，並等待 10 秒確認球、底板、磚塊、分數與結果文字不變。

### 情境六：SC-005，三次確認終止狀態重玩

分別從勝利與 Game Over 畫面按 Space，完成 3 次獨立重玩測試。每次確認恢復 45 塊磚、`Lives: 3`、`Score: 0`、置中的底板與等待發球的球；再次按 Space 後球才發出。

### 情境七：SC-006，三種桌面視窗尺寸

在至少 3 種桌面瀏覽器視窗尺寸下調整視窗或頁面縮放。確認遊戲區完整可見、沒有被截斷，且主要鍵盤操作仍可完成；調整尺寸不會重置回合。

### 情境八：SC-007，五位第一次玩家理解度

找 5 位第一次接觸網頁版本的玩家，各自觀看勝利或 Game Over 畫面，不先口頭解釋文字。請每位指出目前結果與重新開始方式；至少 4 位必須正確回答。

### 情境九：既有桌面版本回歸

另外啟動 `Day2/prj06_lives_restart.py` 與 `Day2/prj07_win.py`，確認仍可獨立執行；檢查網頁化變更沒有刪除、改名或修改這些檔案。

## 公開部署後驗收

完成 Sites 部署後，在未登入的新瀏覽器視窗開啟公開網址，重做情境一、二與六的最小檢查：頁面可載入、鍵盤可操作、結果畫面可重玩。確認網站不依賴本機開發伺服器或 Python 環境。
