# 使用者介面契約：公開網頁版敲磚塊遊戲

**功能規格**：[../spec.md](../spec.md)

## 公開入口

- 訪客透過公開網址進入單一遊戲頁面。
- 頁面不要求登入、不要求安裝桌面程式，也不要求提供個人資料。
- 頁面標題與說明必須讓訪客知道這是可直接遊玩的敲磚塊遊戲。

## 鍵盤輸入

| 遊戲狀態 | 輸入 | 必要結果 |
|----------|------|----------|
| 進行中、球等待發球 | Space | 球開始移動；按鍵不得使頁面捲動。 |
| 進行中、球已發出 | Left／Right 或 A／D | 底板在左右邊界內移動；放開按鍵後不因按鍵事件留下額外加速。 |
| 進行中 | Space | 不重置正在進行的回合；只維持既有發球行為。 |
| 勝利（Won） | Space | 完整重置回合並回到 45 塊磚、3 次生命、0 分與等待發球。 |
| Game Over | Space | 完整重置回合並回到 45 塊磚、3 次生命、0 分與等待發球。 |
| 任一狀態 | Escape | 不關閉瀏覽器、不改變回合狀態。 |
| 勝利或 Game Over | Left／Right、A／D 或其他按鍵 | 不移動物件、不改變分數、生命、磚塊或結果。 |

## 焦點與瀏覽器行為

- 頁面載入後遊戲容器或 Canvas 必須可取得鍵盤焦點，讓玩家不需先點擊非遊戲區即可使用鍵盤。
- 遊戲相關按鍵的預設瀏覽器行為不得覆蓋遊戲操作；尤其 Space 不得讓頁面意外捲動。
- 頁面失去焦點後，重新取得焦點時不得自動發球；玩家仍需按 Space。
- 縮放頁面或調整桌面視窗只改變遊戲區的顯示大小，不得重置或改變回合狀態。

## 可見狀態

### 初始／進行中

- 顯示完整遊戲區、45 塊磚、底板與球。
- 顯示 `Lives: 3` 與 `Score: 0`；擊破磚塊後分數增加 10。
- 顯示簡短操作提示，至少指出 Space、Left／Right 與 A／D 的用途。
- 物件在畫面中可辨識，遊戲區在桌面視窗縮小時仍維持完整比例。

### 勝利

- 最後一塊磚消失後，在下一個可見畫面內顯示 `You Win` 與 `Press SPACE to restart`。
- 保留最後分數、生命數與清板後的版面。
- 球、底板、磚塊與碰撞不再更新；方向鍵與 A／D 不改變畫面。

### Game Over

- 生命歸零且仍有磚塊時顯示 `Game Over` 與 `Press SPACE to restart`。
- 保留當局最後分數、生命數與尚存磚塊。
- 球、底板、磚塊與碰撞不再更新。

## 可讀性與輔助資訊

- 遊戲容器需有可辨識的名稱或標籤，說明其為敲磚塊遊戲。
- 生命、分數與結果文字不得只存在於無法被輔助技術讀取的圖形中；頁面應提供對應的可讀狀態文字。
- 結果文字應在狀態改變時更新，讓使用者能辨識勝利與 Game Over 的差異。
- 色彩用於區分磚塊列時，不能是理解遊戲結果的唯一依據；結果必須同時有文字。

## 重置契約

從勝利或 Game Over 按下 Space 後，下一個可見回合 MUST 顯示：

- 45 塊存活磚。
- `Lives: 3` 與 `Score: 0`。
- 置中的底板與位於底板上方等待發球的球。
- 不顯示 You Win 或 Game Over。
- 玩家再次按 Space 後球才開始移動。

## Sites 部署契約

- 只部署已通過本機建置與人工驗收的網站版本。
- 公開部署後，未登入的新瀏覽器視窗可直接載入遊戲頁面。
- 網站不依賴本機 Python 環境、桌面 Pygame 視窗、資料庫或登入服務。
- Sites 設定只包含網站專案識別與必要的邏輯綁定；本功能不配置 D1、R2、Auth 或秘密。
