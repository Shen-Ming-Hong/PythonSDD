# 快速驗收：敲磚塊勝利流程

## 前置條件

- 從專案根目錄執行命令。
- 專案虛擬環境位於 `.venv/`。
- 已安裝固定版本依賴 `pygame==2.6.1`。
- 手動驗收時準備鍵盤、計時工具，以及 5 位第一次接觸本版本的玩家。

## 靜態檢查

完成實作後執行語法檢查：

```bash
./.venv/bin/python -m py_compile Day2/prj07_win.py
```

預期結果：命令成功結束，沒有語法錯誤。

## 啟動新檢查點

啟動新的檢查點：

```bash
./.venv/bin/python Day2/prj07_win.py
```

預期結果：開啟 800×600 遊戲視窗，顯示既有版面、底板、球、`Lives: 3` 與 `Score: 0`。

## 驗收情境

### 情境一：確認既有進行中行為

按 Space 發球並使用既有控制方式遊玩。確認底板移動、球反彈、磚塊碰撞、每塊磚 10 分計分與生命遺失都與 `prj06` 一致。

### 情境二：SC-001，三次確認勝利提示時限

進行 3 次彼此獨立的完整清板測試。每次記錄最後一塊磚消失的時間，確認 1 秒內都顯示 `You Win` 與 `Press SPACE to restart`，且抬頭資訊保留最終分數與生命數。

### 情境三：SC-002，三次確認勝利畫面凍結

進行 3 次彼此獨立的勝利凍結測試。每次在勝利畫面記下球、底板、磚塊、分數與生命數，持續等待 10 秒並按方向鍵；10 秒後上述狀態都必須與記錄相同。

### 情境四：SC-003，三次確認勝利後重玩

進行 3 次彼此獨立的勝利重玩測試。每次在勝利畫面按 Space，確認下一個回合都恢復 45 塊磚、`Lives: 3`、`Score: 0`，且球連接在置中的底板上等待發球。

### 情境五：SC-004，三次確認遊戲結束回歸

進行 3 次彼此獨立的失敗測試；每次在尚有磚塊時讓球遺失三次，確認每次都顯示 Game Over 而非勝利。接著每次按 Space，確認都能恢復 45 塊磚、3 次生命、0 分與等待發球狀態。

### 情境六：SC-005，五位第一次玩家確認提示可理解

找 5 位第一次接觸本版本的玩家，各自觀看勝利畫面，不先口頭解釋畫面文字。請每位指出目前結果，以及要如何重新開始；至少 4 位必須只根據畫面文字正確指出已勝利並找出 Space 操作。

### 情境七：確認舊檢查點未受影響

另外啟動 `Day2/prj06_lives_restart.py`，確認它仍可獨立執行，並確認其原始內容未因本功能而改變。
